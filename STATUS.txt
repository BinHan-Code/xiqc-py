xiqc-py — Project Status Snapshot
Date: 2026-05-13
====================================

WHAT THIS IS
------------
A Python library + CLI for the ExtremeCloud IQ Controller (XIQ-C) REST API.
Target: AP/Station/Site inventory, telemetry pipeline feed, RF ML data.
License: Apache 2.0. Repo is PUBLIC.

CURRENT STATE: Core API surface implemented
---------------------------------------------
Auth, HTTP plumbing, five inventory endpoints, two SmartRF endpoints,
CLI commands, pydantic models, and respx-mocked tests are all in place.
35 tests passing. No known bugs.

Files and what's done:

  src/xiqc/exceptions.py   DONE

  src/xiqc/auth.py         DONE

KEY FIELD NAMES (response JSON — needed for pydantic models)
-------------------------------------------------------------
AP config object (from management/v1/aps):
  serialNumber    — primary key / identifier
  apName          — human name
  hostSite        — site name the AP belongs to
  radios[]        — list of radio dicts (mode, channelwidth, radioIndex, txBf)

Station object (from management/v1/stations/query):
  macAddress      — primary key
  ipAddress       — client IP
  (other fields TBD — need real fixture to enumerate)

Site object (from management/v3/sites):
  id              — UUID, primary key
  siteName        — human name
  country         — country string
  timezone        — timezone string
  features        — feature flags

AP stats object (from management/v1/aps/query — "ApTable" dataset):
  ApName, ApSerial, HwType, IP, MAC, SwVersion
  SiteName, SiteUUID, Location
  IsConnected, LastUpdate
  ChannelFreq, ChannelWidth, ChannelUtilization, ChannelUtilizationAdjusted
  ClearChannel, Clients, Noise, Power, Protocol, RadioIndex
  RadioRxOccupancy, RxOccupancy, TxOccupancy, SNR

SmartRF AP object (from management/v2/aps/{serial}/smartrf):
  serialNumber    — AP serial (primary key)
  radios[]        — list of {radioIndex, channel, power, noiseFloor}

SmartRF site object (from management/v4/sites/{siteId}/smartrf):
  siteId          — site UUID (primary key)
  smartrfEnabled  — bool


KEY CONSTRAINTS TO REMEMBER
----------------------------
- All HTTP goes through XiqcClient._request(). Never call httpx directly.
- _request() uses self._root (https://host:port) as base; pass FULL paths
  like /management/v1/aps, /management/v3/sites — never relative paths.
- All auth goes through AuthClient. Never pass tokens inline.
- All responses parse into pydantic models. No raw dict returns.
- CLI commands are thin: env -> client -> format. No business logic.
- Rate limit: <= 2 req/s (already enforced by _throttle in _http.py).
- API versions are MIXED — /v1, /v2, /v3, /v4. Do NOT normalise.
- No real customer data anywhere — synthetic values only.
- Dependency changes need a human decision before adding.
